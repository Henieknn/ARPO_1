## Цель работы

Изучение автоматизации сборки Unity-проекта через интерфейс командной строки: отказ от ручной компиляции через графический редактор, запуск headless-сборки с флагами `-batchmode -nographics -executeMethod`, программное управление процессом через класс `BuildPipeline` и анализ логов сборки.

## Ход работы

### Шаг 1: Инициализация проекта

Создал новый проект на базе официального шаблона 2D Platformer Microgame в Unity Hub (Unity 6000.3.10f1). Открыл проект в редакторе, перешёл в папку `Assets/Scenes/` и убедился, что основная сцена игры `SampleScene.unity` добавлена и активна в окне File -> Build Settings. Запустил проект средствами Unity и изучил структуру проекта и исходный код.

### Шаг 2: Создание C# скрипта сборщика (BuildManager.cs)

В окне Project внутри папки Assets создал служебную папку `Editor` (код в ней выполняется только внутри редактора и не попадает в финальную сборку игры). Внутри неё создал C# скрипт `BuildManager.cs` со статическим методом `BuildWebGL()`, который:

1. Получает список активных сцен из Build Settings (`EditorBuildSettings.scenes`);
2. Конфигурирует `BuildPlayerOptions` (сцены, путь `Builds/WebGL`, платформа `BuildTarget.WebGL`);
3. Запускает компиляцию через `BuildPipeline.BuildPlayer()`;
4. Анализирует `BuildReport`: при успехе логирует время и размер билда и завершает процесс с кодом 0, при ошибке — с кодом 1 (`EditorApplication.Exit`).

### Шаг 3: Отключение сжатия для WebGL

Перешёл в Edit → Project Settings → Player → вкладка WebGL (иконка планеты) → Publishing Settings и переключил параметр Compression Format со значения Gzip на **Disabled**. Это необходимо для корректной работы Live Server и локального запуска веб-версии игры без специальных HTTP-заголовков.

### Шаг 4: Проверка скрипта через интерфейс Unity

Вернулся в редактор Unity и дождался компиляции проекта — ошибок компиляции нет, класс `BuildManager` доступен. Убедился, что в File -> Build Settings добавлена сцена игры `Assets/Scenes/SampleScene.unity`.

### Шаг 5: Локальная сборка через терминал (CLI)

Полностью закрыл редактор Unity (проект нельзя открывать в двух экземплярах одновременно) и запустил автоматическую сборку из PowerShell в корневой папке проекта:

```powershell
& "C:\Program Files\Unity\Hub\Editor\6000.3.10f1\Editor\Unity.exe" -batchmode -nographics -projectPath "C:\Users\vragv\Desktop\Лабы\АРПО\ARPO1" -executeMethod BuildManager.BuildWebGL -quit -logFile build_webgl.log
```

Использованные флаги:
- `-batchmode` — фоновый режим без графических окон редактора;
- `-nographics` — отключение инициализации графического движка и видеокарты;
- `-executeMethod BuildManager.BuildWebGL` — вызов статического C#-метода сразу после открытия проекта;
- `-quit` — автоматическое закрытие Unity после завершения метода;
- `-logFile build_webgl.log` — перенаправление всего вывода консоли в отдельный файл.

Процесс идёт в фоновом режиме, консоль «замирает» на несколько минут.

## Контрольные вопросы

**1. Зачем в команде запуска CLI использовать флаг -nographics и какую роль он сыграет при переносе пайплайна на удаленный сервер в облаке?**

Флаг `-nographics` отключает инициализацию графического движка и видеокарты: редактор работает без создания графического устройства (NullGfxDevice). Это ускоряет запуск и убирает зависимость от GPU. При переносе пайплайна на удалённый сервер роль критическая: облачные CI-раннеры (например, ubuntu-latest в GitHub Actions) — headless-машины без монитора и видеодрайвера, поэтому без `-nographics` Unity просто не сможет инициализировать графику и сборка упадёт.

**2. Что произойдет, если запустить консольную сборку проекта, в настройках Build Settings которого не выбрана ни одна сцена игры? Какая строка кода обрабатывает эту ситуацию?**

Сборка не начнётся: метод `GetScenes()` вернёт пустой массив, после чего сработает защитная проверка `if (levels.Length == 0)` в методе `BuildWebGL()`. В лог выведется ошибка `[CI/CD] Ошибка: В Настройках Сборки (Build Settings) не найдено ни одной активной сцены!`, и процесс Unity корректно завершится с кодом возврата 1 (`ExitWithCode(1)`), что позволит пайплайну понять, что сборка провалилась.

**3. Почему класс BuildManager и его методы обязательно должны быть объявлены как public static?**

Флаг `-executeMethod` вызывает метод через рефлексию без создания экземпляра класса и без открытия графического интерфейса, поэтому требуется статический метод, доступный без инстанса (`public static void BuildWebGL()`). Класс должен быть public, чтобы механизм рефлексии редактора мог его обнаружить из сборки Editor, а метод — static, чтобы вызываться без объекта: при batch-запуске некому создавать экземпляры классов.
